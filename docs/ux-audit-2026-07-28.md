# Aye, Aye — pre-launch UI/UX audit (2026-07-28)

Full walkthrough of both pages (`share/app.html`, `share/board.html`) in a
headless browser at 390×844, 320×568, and 1440×900, driven through every
reachable state — blocked prompts, voice capture, empty, auth-failed, offline,
board errors — via a fixture API harness that reproduces the real server's
response shapes (verified against `bin/ayeaye`). The real server was also
booted to confirm startup and capability probing. Contrast figures are
computed WCAG 2.1 ratios. Visual report with screenshots:
https://claude.ai/code/artifact/85222715-acaf-450e-a3e0-dfa5d1faebb4

> **Status: all 18 findings fixed on 2026-07-28** and re-verified with an
> automated 26-check browser pass. Extra feature added in the same pass: the
> permission prompt card now also docks under the transcript view via a new
> lightweight `GET /api/prompt?pane=` endpoint, so prompts are answerable
> from the overview, terminal, *and* transcript. The findings below stand as
> the record of what was found.

## Verdict

Strong, opinionated UI, close to ready. The core loop — notification → glance
at sessions → answer a permission prompt in two taps — is well designed and
the visual system is coherent across both pages. Before a *public* release,
fix the four high findings: an unhandled render crash on API error payloads,
near-invisible error states, footer status messages that never expire (and
can misdirect), and keyboard/screen-reader inoperability.

## Control flow

Remote is hub-and-spoke around the sessions overview:

```
ntfy push ─→ sessions overview (polls 5s)
              ├─ blocked card → prompt card ─ digit selects → ⏎ on card confirms
              │                 └─ "tell it differently" → terminal + talk
              ├─ tap agent card → transcript (SSE live tail)
              ├─ tap shell card / terminal tab → terminal (auto-fit lease)
              └─ + new agent → directory picker → spawn → terminal
footer (any view): ⏎ · esc · ⌨ type · 🎤 talk → record → review draft → send / send-⏎
```

Board is a filter funnel handing back into the remote:

```
board ─ project chip / milestone card → filtered board
  └─ issue card (URL hash = key) → ticket overlay
        ├─ ▶ run → directory picker → agent spawned with ticket prompt → "open remote →"
        └─ ← back (phone back button works; tickets live in the hash)
```

Deliberate two-step confirm (digit never submits; server never pairs digit
with Enter) is the right safety design for a remote that can approve
`git restore`.

## Findings

### High — fix before public exposure

- **F1 · Error payloads crash the overview renderer.** `loadOverview()` does
  `d.panes.forEach(…)` on 401/error JSON; TypeError on every 5s poll while
  unauthorized. Catch wraps only the fetch. Same shape risk in
  `loadProjects`/`loadRunDirs`. (app.html:655)
- **F2 · Auth-failed and offline states are nearly invisible.** Blank canvas +
  12px footer message reads as "no agents running". Reuse the `.empty`
  pattern in-canvas with the recovery action; stop polling on 401.
  (app.html:513–522, 649–652)
- **F3 · Status messages never expire.** "selected · press ⏎ enter to submit"
  persists for the whole session across views. The footer ⏎ targets the
  *selected* pane, not necessarily the answered card's pane — stale guidance
  invites pressing enter at the wrong agent. Auto-clear ~6s and on view/pane
  change; put guidance on the card. (app.html:403, 743–753, 1044–1057)
- **F4 · Keyboard/screen-reader inoperability.** Pane chips, session cards,
  project rows, board chips/cards/milestones are click-only `<div>`s (no
  tabindex/role/focus); ↑/↓ buttons lack accessible names; `#msg` has no
  aria-live. WCAG 2.1.1 / 4.1.2. (app.html:527–539, 655–716;
  board.html:455–466, 525–543)

### Medium

- **F5 · `--faint` (#5b6078) fails contrast**: 2.9:1 on ground, 2.6:1 on
  panels (AA 4.5:1) — used for the prompt hint, timestamps, pane commands,
  ticket keys. `--muted` passes (4.5–5.1:1); promote instructional text.
- **F6 · Remote has no desktop max-width** — full-width talk button and
  option rows at 1440px. Add a centered ~520px shell. (app.html:32)
- **F7 · Ticket markdown keeps source hard-wraps** (`.mdb p{white-space:
  pre-wrap}`) → ragged mid-sentence breaks on phones; also over-tight table
  cell wrapping ("claud e"). Join single newlines in paragraphs.
  (board.html:260, 277)
- **F8 · Prompt option styling is positional, not semantic.** Option 1 is
  always the green primary; a destructive first option would get the
  endorsing treatment. Green full-width buttons also read as final though
  they only select. Reflect the pending selection on the card.
  (app.html:227–230, 677–699)
- **F9 · Identity loose ends**: `<title>` still "voice remote"; no
  `manifest.json` despite PWA meta tags, so install prompts get defaults.
  (app.html:12)
- **F10 · Board failure states styled as faint notes** identical to "no
  issues here"; no retry near the message. (board.html:107, 429–438)

### Low

- **F11** Agent named twice per card ("CODEX" badge + `codex` cmd).
- **F12** Plain-shell cards (e.g. `dots:1 fish`) look like broken agent
  cards; tag them "shell" or group them.
- **F13** Animations ignore `prefers-reduced-motion` (needglow, breathe,
  recpulse).
- **F14** Expanded tool cards repeat the summary as the first content line.
- **F15** Panes labeled by window index though `window_name` is collected —
  "ayeaye:dev" beats "ayeaye:1". (bin/ayeaye:193–206, app.html:530)
- **F16** Done-column cards keep loud URGENT/HIGH chips; mute on `.iss.done`.
- **F17** Footer ⏎/esc/talk stay enabled with no pane selected; fail after
  the fact.
- **F18** Board refreshes only on >60s visibility return or manual refresh;
  consider a slow idle poll.

## What's excellent — keep

Blocked-first sorting + once-per-question ntfy; two-step prompt confirm
enforced server-side; voice pipeline with reviewable cleaned-up drafts and a
90s abort; capability probing that greys features up front; the tmux resize
lease (acquire/renew/beacon-release/sweeper, damped drift-heal); transcript
ergonomics (collapsed tool noise, scroll pinning, reconnect on tab return);
ticket-key linkification with real project keys and hash-routed tickets;
data-free unauthenticated pages and the one-time token bookmark.

## Suggested order of work

1. Guard fetch renderers (F1); stop polling on 401 — ~15 lines.
2. In-canvas error states on both pages (F2, F10).
3. Expire `#msg`; move prompt guidance onto the card (F3, part of F8).
4. Keyboard/AT pass: buttons or role/tabindex/keydown, aria-labels,
   `aria-live` on #msg, focus-visible styles (F4) — largest item.
5. Promote hints out of `--faint` (F5); reduced-motion query (F13) — CSS.
6. Remote max-width (F6); markdown paragraph reflow (F7).
7. Title rename + manifest.json (F9).
8. Lows (F11–F18) as taste dictates.
